Embedding 星圖：力導向放射視覺化 已實作並驗證

日期 2026-06-12  ·  狀態 已實作  ·  套件 react-force-graph-2d  ·  布局 力導向放射  ·  範圍 全語料星雲(17 段) + 高亮命中

01一句話結論與選型

在「問答 / 搜尋對比」之外，新增一個 Embedding 星圖 分頁：把使用者問題放在畫面中心， 全部履歷段落當作環繞的星雲，每個段落依「與問題的餘弦相似度」被彈簧拉近或推遠， 本次檢索命中的 top-k 用 亮色粗邊 + 流動粒子 + 光暈 點亮，其餘為暗淡星點。

選定 react-force-graph（2D 版）。它就是 d3-force 的好用封裝：力導向放射是預設行為、 邊上有現成的方向性流動粒子、節點可用 canvas 自由繪製光暈，與 React 18 相容且自帶 TypeScript 型別。

取捨先講清楚：力導向的節點位置代表「相對親疏」（離中心越近＝與問題越相似）， 不是 1024 維 embedding 空間的真實幾何投影。要「真實座標」得做 PCA/UMAP 降維——但那是你沒選的方向， 且語料 17 段，降維意義不大。力導向的相對親疏在這個規模反而更直覺、更好看。

02放射原理：距離怎麼變成位置

力導向圖是一場物理模擬：每條邊是一根彈簧（理想長度由我們指定），節點之間有電荷斥力讓彼此散開。 我們把每個段落用一條邊連到中心的「問題」節點，並把彈簧的理想長度設成「餘弦距離」的函數—— 相似度越高（距離越小）→ 彈簧越短 → 段落被拉得越靠近中心。模擬鬆弛後，自然形成「以問題為圓心的相似度地形」。

03資料映射

視覺屬性來自什麼
節點離中心的遠近彈簧理想長度 = f(餘弦距離)；相似度高 → 近
節點大小命中節點依相似度放大（6 + sim×4）；一般段落固定小點
節點 / 邊顏色問題＝青墨、命中＝朱砂、其餘＝暗灰（讀目前亮/暗主題色票）
邊粗細命中粗、其餘細
流動粒子僅命中邊有，數量可依相似度（神經訊號傳遞感）
標籤問題與命中節點顯示來源標籤；hover 顯示相似度 %

相似度定義：sim = clamp(1 − distance, 0, 1)（pgvector <=> 是餘弦距離，∈[0,2]）。與現有 ScoreBar 一致。

04後端契約（小改，約 30 行）

你選「全語料 + 高亮」，只需要 query↔每個 doc 的距離，不必傳 embedding 向量、不必算 pairwise。

4.1 rag.py：新增 retrieve_all()

沿用既有 _to_vector_literal() 與 <=> 寫法，只是拿掉 LIMIT、多回一個 id 當節點唯一鍵：

def retrieve_all(question_vec: list[float]) -> list[dict]:
    """回傳 query 對「全部」docs 的餘弦距離(不 LIMIT),依距離排序。
    供 /graph 畫全語料星雲;rows 已排序,前 k 筆即本次命中。"""
    vec_literal = _to_vector_literal(question_vec)
    with get_conn() as conn, conn.cursor() as cur:
        cur.execute(
            """
            SELECT id, content, source, embedding <=> %s::vector AS distance
            FROM docs
            ORDER BY distance;
            """,
            (vec_literal,),
        )
        rows = cur.fetchall()
    return [
        {"id": id_, "content": content, "source": source, "distance": float(distance)}
        for (id_, content, source, distance) in rows
    ]

4.2 main.py：新增 POST /graph

# import 加上 retrieve_all
from rag import build_prompt, keyword_search, retrieve, retrieve_all

class GraphNode(BaseModel):
    id: int
    content: str
    source: str | None = None
    distance: float
    hit: bool                      # 是否為本次 top-k 命中

class GraphResponse(BaseModel):
    question: str
    k: int
    nodes: list[GraphNode]

@app.post("/graph", response_model=GraphResponse)
def graph(req: AskRequest, k: int = 4) -> GraphResponse:
    """全語料語意地圖:回傳 query 對所有段落的距離,前 k 筆標記命中。"""
    question = req.question.strip()
    if not question:
        raise HTTPException(status_code=400, detail="question 不可為空")
    try:
        question_vec = ollama_client.embed(question)
    except Exception as e:
        raise HTTPException(status_code=502, detail=f"Embedding 失敗:{e}")
    rows = retrieve_all(question_vec)              # 已依距離排序
    nodes = [GraphNode(**row, hit=(i < k)) for i, row in enumerate(rows)]
    return GraphResponse(question=question, k=k, nodes=nodes)

5.2 api.ts：新增型別與呼叫

export interface GraphNode {
  id: number; content: string; source: string | null; distance: number; hit: boolean;
}
export interface GraphResponse { question: string; k: number; nodes: GraphNode[]; }

export async function fetchGraph(question: string): Promise<GraphResponse> {
  const resp = await fetch("/api/graph", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ question }),
  });
  if (!resp.ok) throw new Error(await parseError(resp));
  return (await resp.json()) as GraphResponse;
}

5.3 新元件 EmbeddingGraph.tsx（核心片段）

重點：量測容器尺寸、把回應組成 graphData、用 ref 設定力、用 nodeCanvasObject 自畫光暈。

import { useEffect, useMemo, useRef, useState } from "react";
import ForceGraph2D, { type ForceGraphMethods } from "react-force-graph-2d";
import type { GraphResponse } from "../api";

// cos 距離 → 邊長(px):min-max 正規化把窄距離拉開到 70~380,層次才明顯
const linkLen = (d: number) => 70 + (dmax > dmin ? (d - dmin) / (dmax - dmin) : 0) * 310;

export default function EmbeddingGraph({ data, theme }:
    { data: GraphResponse; theme: "light" | "dark" }) {
  const fgRef = useRef<ForceGraphMethods>();
  const wrapRef = useRef<HTMLDivElement>(null);
  const [size, setSize] = useState({ w: 800, h: 520 });

  // react-force-graph 需要明確 width/height,用 ResizeObserver 量容器
  useEffect(() => {
    if (!wrapRef.current) return;
    const ro = new ResizeObserver(([e]) => setSize({ w: e.contentRect.width, h: 520 }));
    ro.observe(wrapRef.current);
    return () => ro.disconnect();
  }, []);

  // 中心 query 節點(fx/fy 固定在 0,0) + 全 docs;每個 doc 連一條邊到中心
  const graphData = useMemo(() => ({
    nodes: [
      { id: "__q__", kind: "query", label: data.question, fx: 0, fy: 0 },
      ...data.nodes.map((n) => ({
        id: n.id, kind: n.hit ? "hit" : "doc",
        source: n.source, content: n.content,
        distance: n.distance, sim: Math.max(0, 1 - n.distance),
      })),
    ],
    links: data.nodes.map((n) => ({ source: "__q__", target: n.id, distance: n.distance, hit: n.hit })),
  }), [data]);

  // 設定力:link 距離依相似度、charge 斥力散開
  useEffect(() => {
    const fg = fgRef.current; if (!fg) return;
    fg.d3Force("link")?.distance((l: any) => linkLength(l.distance));
    fg.d3Force("charge")?.strength(-140);
    fg.d3ReheatSimulation();
  }, [graphData]);

  const C = theme === "dark"
    ? { query: "#f0e9db", hit: "#f26a48", doc: "#5a5345", line: "#3a342a", text: "#f0e9db" }
    : { query: "#156b62", hit: "#cf4327", doc: "#b9ad97", line: "#d4c9b4", text: "#211c16" };

  return (
    <div ref={wrapRef} className="graph-wrap">
      <ForceGraph2D
        ref={fgRef} width={size.w} height={size.h} graphData={graphData}
        backgroundColor="transparent" cooldownTicks={120}
        onEngineStop={() => fgRef.current?.zoomToFit(400, 60)}
        linkColor={(l: any) => (l.hit ? C.hit : C.line)}
        linkWidth={(l: any) => (l.hit ? 2 : 0.6)}
        linkDirectionalParticles={(l: any) => (l.hit ? 4 : 0)}
        linkDirectionalParticleWidth={2.5}
        linkDirectionalParticleColor={() => C.hit}
        nodeLabel={(n: any) => n.kind === "query" ? n.label
          : `${n.source ?? "未標註"} · 相似度 ${Math.round(n.sim * 100)}%`}
        onNodeClick={(n: any) => n.kind !== "query" && onPick?.(n)}
        nodeCanvasObject={(node: any, ctx, scale) => {
          const r = node.kind === "query" ? 9 : node.kind === "hit" ? 6 + node.sim * 4 : 3;
          const color = C[node.kind];
          if (node.kind !== "doc") {            // 光暈(query/命中才畫)
            const g = ctx.createRadialGradient(node.x, node.y, 0, node.x, node.y, r * 3);
            g.addColorStop(0, color + "66"); g.addColorStop(1, color + "00");
            ctx.fillStyle = g; ctx.beginPath(); ctx.arc(node.x, node.y, r*3, 0, 2*Math.PI); ctx.fill();
          }
          ctx.fillStyle = color; ctx.beginPath(); ctx.arc(node.x, node.y, r, 0, 2*Math.PI); ctx.fill();
          if (node.kind !== "doc") {            // 標籤
            ctx.font = `${12/scale}px "Noto Sans TC", sans-serif`;
            ctx.fillStyle = C.text; ctx.textAlign = "center";
            ctx.fillText(node.kind === "query" ? "問題" : node.source, node.x, node.y + r + 12/scale);
          }
        }}
      />
    </div>
  );
}

三個整合注意點：

  • 尺寸：元件需要數值 width/height，用 ResizeObserver 量容器（不能只靠 CSS 100%）。
  • 主題色：canvas 不吃 CSS 變數，所以把 theme 當 prop 傳入、在元件內定義色票物件；切換深淺色時 props 改變會自動重繪。
  • StrictMode：dev 下會雙掛載，force 設定放 useEffect 並依 graphData 重跑即可；graphData 用 useMemo 避免每次 render 重啟模擬。

06力學與視覺參數（可調）

參數建議起點作用
link 距離70 + t×310
t=(d−dmin)/(dmax−dmin)		min-max 正規化：bge-m3 距離擠在 0.40～0.59 窄區間，線性映射層次出不來，正規化後拉開到 70～380px
charge 斥力-150越負越散；節點多時調更負避免擠成團
命中節點半徑6 + sim×4越相似越大
流動粒子數命中 4、其餘 0神經訊號傳遞感；可改 round(sim×6)
cooldownTicks120模擬幀數；配 onEngineStop→zoomToFit 自動取景
query 固定fx=0, fy=0釘住中心，確保「放射」而非整團漂移

08風險與取捨

  • 位置非真實幾何（已於 01 說明）：力導向是相對親疏，不是 embedding 空間投影。要寫實得降維。
  • 全語料規模：目前 17 段，canvas 2D 輕鬆。若未來灌到上百、上千段，2D 仍可，但要考慮節點上限或改 WebGL/3D 版。
  • 命令式 API：react-force-graph 用 ref 呼叫方法（d3Force/zoomToFit），與 React 宣告式略有摩擦，集中在 useEffect 處理即可。
  • 每次提問 = 一次 embed：和 /ask、/compare 一樣會打 Ollama 一次，GPU 上很快。
  • 距離尺度（實測）：bge-m3 的距離擠在 0.40～0.59 窄區間，所以改用 min-max 正規化把這批距離拉開，放射層次才明顯。
  • canvas 座標 NaN（實作踩到的坑）：力導向模擬頭幾幀節點 x/y 還是 NaN，傳進 createRadialGradient 會讓整張圖畫不出來。nodeCanvasObject 第一行用 Number.isFinite 擋掉即可。另以 ErrorBoundary 包住星圖，任何渲染錯誤只影響該區、不整頁白屏。
